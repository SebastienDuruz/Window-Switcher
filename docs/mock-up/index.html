  • Each row shows ShortWindowTitle and, in gray on the right, the process name (truncated first when space runs out). Rows cannot be selected.
  • A left click on a row activates its window, exactly like a click on its preview (that row then becomes the highlighted one; "Hide active preview" applies too). The pointer becomes a hand over the rows.
  • The row of the active window has a translucent background in the "Highlight color" (25% opacity), like the border of its preview; the text does not move. It follows the highlighted preview (click on a preview or keybind).
  • When no window matches the filters, the list is replaced by a short explanation and an "Open filters" link that opens Settings › Filters.
  • "Bring preview here" moves the preview of that window to the right of the main window, top-aligned (to the left when the right side lacks room, always inside the screen), and raises it above other windows, so a lost preview can be found and placed again. A preview hidden by "Hide active preview" is shown again; activating its window again hides it again.
  • Right-clicking a row also opens the same actions as a preview: "Add to blacklist" (adds the full title to Settings › Filters › Hidden windows), "Add to temp blacklist" (hides the window until Window Switcher restarts) and "Rename window".
  • "Settings" is a top-level menu item without a submenu: it opens the Settings window on the last page used.

  • The label sits 2 px inside the top-left corner (clear of the active border) on a translucent dark background (black at 65% opacity, small rounded bottom-right corner) so it stays legible on light or same-colored captures; a long title is cut with an ellipsis. The sample in Settings › Previews › Appearance shows the same label.
  • A 2 px border in the "Highlight color" (#E3008C by default) surrounds the preview of the active window; a 4 px yellow border marks a pending capture selection (PendingSelectionBorderBrush).
  • A preview without a saved position opens in the first free slot of a grid filled row by row from the top-left corner of the primary screen's working area (16 px margin, 8 px gap), so new previews never open on top of each other. The slot is freed when the preview closes; once a preview is moved, its saved position is used instead.
  • Left click activates the window; dragging moves the preview (when "Move windows" is on); right click opens the context menu above. "Reset preview stream" only appears when the capture selection can be reset.

Reset all settings
Restore the default configuration? Filters, keybinds, the preview layout and screen capture selections are reset too.
  • One window with a sidebar groups every configuration screen, including About. The sidebar of the first window is clickable. Every change is saved as soon as it is made.
  • General › Reset: "Reset layout…" (ResetFloatingWindowSettings) and "Reset settings…" (ResetUserSettings) both ask for confirmation in a modal dialog ("Reset preview layout": "Forget the saved position and size of every preview?"); closing the dialog cancels. "…" marks the dialog. Both resets also move the open previews back to the default layout (default size, first free slots), so the old layout is not saved again when they close.
  • Previews › Display: "Show floating previews" hides every preview window when turned off (their capture is paused, so no Wayland picker opens); windows are then switched from the main list or with keybinds, and "Bring preview here" disappears from the main list menu. "Live content" and "Hide active preview" are disabled while previews are hidden.
  • Previews › Size: "Per preview" and "Fixed" are one choice. Under "Per preview", resizing by dragging (ResizeWindows) can be turned off; it is disabled with "Fixed". The size fields (10 to 2000 px) are only enabled with "Fixed".
  • The app keeps a fixed accent color (blue, the Fluent default) for its controls (switches, radio buttons, sidebar, focus, links); the "Highlight color" only colors the previews (labels, active border) and the active row of the main list, so a light or yellow highlight no longer makes the interface hard to read.
  • Previews › Screen capture is only shown when CanResetAllPreviews is true (remembered Wayland capture selections).
  • Filters: "Shown windows" matches part of the title, "Hidden windows" the full title; matching ignores case. A row is removed only with its ✕ button; selecting a row does nothing else. Enter in a text box is the same as "Add".
  • Keybinds: one table, one row per target: the built-in actions (constants of KeybindBuiltInTargets), then the client windows (title (process), sorted alphabetically). Each shortcut is a chip with its ✕ remove button; "+" opens the capture in the same row ("Press the shortcut…", then the captured keys) with Save and Cancel; only one row captures at a time. A rejected shortcut (duplicate, conflict) keeps the capture open. The status line is green for a success and red for an error. The red banner only appears when global keyboard access has an issue (Linux); its text depends on the diagnostic.
  • About: "Update" is only visible when CanUpdateNow is true. Possible update messages: "Checking for updates...", "Version X is available.", "You are up to date.", "Update check failed: …", "Preparing update...". On Windows, the preview mode reads "Desktop Window Manager (DWM)".
  • System values (OS, paths, dependencies) are examples.
