Restore the default configuration? Filters, keybinds and the preview layout are reset too.
  • One window with a sidebar groups every configuration screen. The sidebar of the first window is clickable. Every change is saved as soon as it is made.
  • General › Reset: "Reset layout…" (ResetFloatingWindowSettings) and "Reset settings…" (ResetUserSettings) both ask for confirmation in a modal dialog ("Reset preview layout": "Forget the saved position and size of every preview?"); closing the dialog cancels. "…" marks the dialog.
  • Previews › Size: "Per preview" and "Fixed" are one choice. Under "Per preview", resizing by dragging (ResizeWindows) can be turned off; it is disabled with "Fixed". The size fields (10 to 2000 px) are only enabled with "Fixed".
  • Previews › Screen capture is only shown when CanResetAllPreviews is true (remembered Wayland capture selections).
  • Filters: "Shown windows" matches part of the title, "Hidden windows" the full title; matching ignores case. A row is removed only with its ✕ button; selecting a row does nothing else. Enter in a text box is the same as "Add".
  • Keybinds: "Actions" targets are the constants of KeybindBuiltInTargets; "Client windows" targets read title (process), sorted alphabetically. "Add shortcut" enters capture mode (initial text: "Press the shortcut to capture"); the capture row is only visible while capturing. The red banner only appears when global keyboard access has an issue (Linux); its text depends on the diagnostic. The status line uses ErrorTextBrush for every message.
  • About: "Update" is only visible when CanUpdateNow is true. Possible update messages: "Checking for updates...", "Version X is available.", "You are up to date.", "Update check failed: …", "Preparing update...". On Windows, the preview mode reads "Desktop Window Manager (DWM)".
  • System values (OS, paths, dependencies) are examples.
